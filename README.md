# Quiz App

Веб-приложение для проведения интерактивных викторин в реальном времени.

Проект представляет собой MVP, в котором организатор может создавать и запускать викторины, а участники — подключаться к игровой комнате по коду и отвечать на вопросы в режиме реального времени.

## Возможности

### Организатор

- регистрация и авторизация;
- создание и удаление викторин;
- добавление вопросов;
- редактирование и удаление вопросов;
- настройка вариантов ответов;
- выбор одного или нескольких правильных ответов;
- добавление изображения к вопросу;
- настройка времени на вопрос;
- создание игровой комнаты;
- запуск и завершение игры;
- просмотр результатов участников;
- просмотр истории проведённых игр;
- автоматическое сохранение результата организатора в истории.

### Участник

- подключение к игре по коду комнаты;
- указание имени участника;
- получение вопросов в реальном времени;
- отправка одного или нескольких вариантов ответа в течение установленного времени;
- просмотр итогового лидерборда;
- сохранение собственного результата в истории;
- просмотр истории завершённых игр.

### Игровая логика

- синхронизация состояния игры через Socket.IO;
- автоматический таймер вопроса;
- подсчёт правильных ответов;
- формирование лидерборда;
- поддержка вопросов SINGLE и MULTIPLE;
- поддержка изображений в вопросах;
- проверка ответов на сервере;
- сохранение результатов в PostgreSQL;
- автоматическое создание записей в постоянной истории игр.

## Архитектура

Приложение построено по клиент-серверной архитектуре:

```text
┌──────────────────────────────┐
│          React + Vite        │
│           Frontend           │
└──────────────┬───────────────┘
               │
        HTTP / REST API
               │
               ▼
┌──────────────────────────────┐
│       Node.js + Express      │
│          Backend             │
└──────────────┬───────────────┘
               │
       ┌───────┴────────┐
       │                │
       ▼                ▼
   Prisma           Socket.IO
       │                │
       ▼                ▼
 PostgreSQL       Real-time game
```

REST API используется для работы с постоянными данными, а Socket.IO — для передачи игровых событий в реальном времени.

## Основные сущности базы данных

```text
User
 ├── Quiz
 │    └── Question
 ├── Room
 │    └── Player
 │         └── Answer
 └── GameHistory

Quiz
 ├── Room
 └── GameHistory
```

- `User` — пользователь системы;
- `Quiz` — викторина;
- `Question` — вопрос;
- `Room` — игровая комната;
- `Player` — участник конкретной игровой сессии;
- `Answer` — ответ участника;
- `GameHistory` — постоянная история завершённых игр.

Для `Room` хранится `hostId`, позволяющий определить организатора конкретной игровой сессии.
Пользователь может быть организатором одной комнаты и участником другой.
`GameHistory` не зависит от временных записей `Player` и `Answer` и хранит роль пользователя (`HOST` или `PLAYER`), код комнаты, результат и дату игры.

# Установка и запуск

## Требования

Перед запуском необходимо установить:

- Node.js;
- npm;
- PostgreSQL;
- Git.

Проверить установку Node.js и npm:

```bash
node -v
npm -v
```

Проверить PostgreSQL можно через `psql` или PostgreSQL Server/pgAdmin.

---

## 1. Клонирование репозитория

```bash
git clone https://github.com/Sahated/quiz-app.git
cd quiz-app
```

Структура проекта:

```text
quiz-app/
├── client/        # React frontend
├── prisma/        # Prisma schema и миграции
├── scripts/        # служебные скрипты миграции данных
├── src/            # Node.js backend
├── socket-test.js
├── package.json
└── README.md
```

> Backend находится в корне проекта, frontend — в каталоге `client`.

---

## 2. Установка зависимостей backend

Из корня проекта:

```bash
npm install
```

---

## 3. Настройка PostgreSQL

Создайте базу данных PostgreSQL для проекта.

Например:

```text
Название базы: quiz_app
Пользователь: postgres
Пароль: <ваш пароль>
Порт: 5432
```

После этого создайте файл `.env` в корне проекта:

```env
DATABASE_URL="postgresql://postgres:YOUR_PASSWORD@localhost:5432/quiz_app"
JWT_SECRET="your_secret_key"
PORT=3000
```

Замените:

- `YOUR_PASSWORD` на пароль пользователя PostgreSQL;
- `your_secret_key` на собственный секретный ключ.

> Файл `.env` не следует добавлять в GitHub.

---

## 4. Настройка Prisma

После настройки `.env` выполните:

```bash
npx prisma generate
```

Для применения миграций проекта выполните:

```bash
npx prisma migrate dev
```

После этого сгенерируйте Prisma Client:

```bash
npx prisma generate
```

После этого Prisma Client будет готов к работе.

При необходимости посмотреть содержимое базы данных:

```bash
npx prisma studio
```

---

## 5. Запуск backend

Из корня проекта:

```bash
npm run dev
```

Backend запускается на:

```text
http://localhost:3000
```

# Использование приложения

## Организатор

2. Зарегистрировать аккаунт.
3. Выполнить вход.

4. Подключиться к комнате.
5. Дождаться запуска игры.
6. Отвечать на вопросы в установленное время.
7. После завершения посмотреть итоговый лидерборд.
8. Открыть раздел «История» и посмотреть результат своего участия.

# Реализация реального времени

Для игровой части используется Socket.IO.

Основные события включают:

- подключение организатора;
- подключение участника;
- запуск игры;
- начало вопроса;
- отправку ответа;
- переход к следующему вопросу;
- завершение игры;
- отключение участника;
- подключение организатора только при подтверждении его роли в комнате.

Сервер хранит актуальное состояние игры и передаёт изменения подключённым клиентам.

Организатор комнаты определяется по `Room.hostId`. Это позволяет одному пользователю быть организатором одной игры и участником другой.

Правильный ответ не передаётся клиенту вместе с вопросом. Проверка ответа выполняется на сервере.

# История игр

После завершения игры сервер автоматически создаёт записи в `GameHistory`.

Для каждого пользователя сохраняются:

- роль в игре: `HOST` или `PLAYER`;
- название викторины;
- код комнаты;
- количество набранных очков;
- место в лидерборде для участника;
- дата проведения игры.

История хранится отдельно от временных данных игровой комнаты. Поэтому удаление завершённой комнаты в дальнейшем не должно приводить к потере сохранённых результатов.

Для существующих завершённых игр была выполнена миграция результатов в `GameHistory`.
